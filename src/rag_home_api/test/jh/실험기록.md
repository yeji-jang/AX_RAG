### 2-3. 법령 보강 (11-24~25, 버전 이름은 v1 유지)

- 이유: 법령 원문이 3개(주택임대차보호법·시행령·부동산거래신고법)뿐. 이사 흐름 주제별로 보니 임대차 신고 금액 기준·원상회복·전입신고 기한의 법적 근거가 약함.
- 방법: 국가법령정보센터 HTML(법제처 원문)로 받음. PDF보다 조·항·호 구조가 정확하고 시행일·법령 번호가 함께 남음.
- 법 전체가 아니라 관련 조문만 넣음. 관련 없는 조문(매매 신고, 주민등록증 등)은 검색에서 오답 후보가 됨. 고른 조문은 `export_jsonl.LAW_ARTICLE_RANGE`에 적어 두고 문서목록 비고에도 자동 기록.

| 주제 | 법령 | 넣은 조문 |
| --- | --- | --- |
| 임대차 신고 | 부동산거래신고법 시행령 | 제4조의3(신고 대상: 보증금 6천만 원 초과 또는 월 차임 30만 원 초과, 지역), 제20조(과태료) |
| 원상회복·중도 해지·보증금 | 민법 | 제618~654조 임대차 36개(삭제된 제651조 제외) |
| 전입신고 | 주민등록법 | 제10·11·16·16조의2·18조, 제29조의2(전입세대확인서), 제40조(과태료) |

- 넣지 않음: 공공주택 특별법 — 자격은 공고문에 구체적으로 있고, 법 본문은 사업자·분양 조항 위주.
- 결과: 법령가이드 426 → 471줄(조문 112 → 157), 전체 4,940 → 4,985줄, 문서목록 421 → 424행. 공공임대·청년안심 JSONL과 기존 조문의 id·본문은 변화 없음(git diff 확인).
- 조문 id는 법 전체 순서 번호를 유지(예: `LAW_CIVIL_본칙_627` = 민법 제618조).

## 5. 평가셋 [팀 공유]

### 5-1. 만든 방법

- 사용자 질문(사회초년생이 실제로 궁금한 것)에서 출발하고, 비는 이사 단계는 문서(조문·공고)에서 골라 채움.

## 6. A/B 검색 실험 — dev

- dev 10문항(답 있음 8 + 답 없음 2)으로만 봄. test는 실행 안 함.

### 6-1. 설정 [개인]

| 항목 | 값 |
| --- | --- |
| 청크 | `jh_500`, `jh_1000`을 r0~개선 3 모두 비교 → `jh_1000` 선택 (6-2 청크 선택 참고) |
| A | `vectorstore.as_retriever(search_kwargs={"k": 5})`. 거의 같은 글 합치기를 할 때는 k=20을 받아 거른 뒤 상위 5. 법령·가이드만 찾을 때는 `filter` |
| B | `BM25Retriever.from_documents(청크, preprocess_func=kiwi_tokenizer)`(k=20) + 벡터 검색기(k=20) → `EnsembleRetriever(retrievers=[bm25, vector], weights=[0.5, 0.5])`(안에서 RRF, c=60) → 상위 5 |
| BM25 단어 (`kiwi_tokenizer`) | r0~개선 2: 명사·숫자·외국어·한자·어근·동사·형용사(NNG·NNP·NR·SN·SL·SH·XR·VV·VA) / 개선 3: 동사·형용사(VV·VA) 빼고 흔한 일반 명사(때·경우·얼마·몇·사항·해당·등·것·수·후) 제외. 질문·청크에 같은 규칙 |
| 거의 같은 글 합치기 | 개선 1부터: `EmbeddingsRedundantFilter(similarity_threshold=0.95)`(기본값) → `DocumentCompressorPipeline` → `ContextualCompressionRetriever(base_compressor, base_retriever=A 또는 B)`. 후보끼리 임베딩 코사인 유사도 0.95 초과면 둘 중 하나를 뺌 |
| 문서 종류 나눠 찾기 | 개선 2부터: `RunnableBranch((조건, 전체 검색기), 법령·가이드 검색기)`. 조건 = 질문에 공고·단지를 가리키는 말(공고·모집·행복주택·청년안심·LH·SH·단지 등, 주택형 `14A`, 역 이름 `○○역`)이 있음. 없으면 법령·가이드(`일반 전월세 법령`·`가이드`, jh_1000 중 545청크)에서만 찾음. A는 `as_retriever`의 `filter`, B는 법령·가이드 청크만으로 만든 `BM25Retriever`(`BM25Retriever`에 거르기 기능 없음) |
| 단계 선택 | `retrieve.PRESETS`(r0·dedupe·route·tok), `run.py --preset` |

- BM25용 청크는 JSONL을 같은 설정으로 다시 잘라 만듦. PGVector 청크와 ID 100% 일치 확인(18,151 / 9,974).

### 품질 4항목: 로컬 참고 평가

- Context Precision은 질문에 등록한 사실·조건 발췌를 실제로 포함하는 청크 수/반환 청크 수임. 답변 가능 문항만 대상으로 하는 등록 근거 기반 대용 지표이며 의미상 모든 유용한 청크를 포괄하지 않음. 질문과 관련된 부가 설명 청크도 등록되지 않았으면 분자에서 빠질 수 있음.
- Context Recall은 실제 상위5개에 정확한 근거 발췌가 있는 필수 사실 수/전체 필수 사실 수임. DEV 필수 사실9개, TEST21개임. 별도 조건의 전체 확보는 위 표에서 따로 계산함.
- Faithfulness는 실제 answered 응답의 모든 중요한 주장(추가 설명 포함)이 실제 제공된 청크에 지지되는지 로컬 대조한 통과 응답 수/answered 응답 수임. 보류·호출 오류는 이 분모에서 제외하며 위 표에 별도 보고함.
- Answer Relevance는 질문의 법적 쟁점에 직접 답하는지 로컬 대조한 통과 응답 수/완료 응답 수임. 값·조건이 틀려도 주제에 답하면 관련성은 통과할 수 있으나 정답은 별도임. 답변 가능 문항의 보류는 미충족, 예상 근거 부족의 안전한 보류는 충족으로 셈.
