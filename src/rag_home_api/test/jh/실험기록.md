### 2-3. 법령 보강 (11-24~25, 버전 이름은 v1 유지)

- 이유: 법령 원문이 3개(주택임대차보호법·시행령·부동산거래신고법)뿐. 이사 흐름 주제별로 보니 임대차 신고 금액 기준·원상회복·전입신고 기한의 법적 근거가 약함.
- 방법: 국가법령정보센터 HTML(법제처 원문)로 받음. PDF보다 조·항·호 구조가 정확하고 시행일·법령 번호가 함께 남음.
- 법 전체가 아니라 관련 조문만 넣음. 관련 없는 조문(매매 신고, 주민등록증 등)은 검색에서 오답 후보가 됨. 고른 조문은 `export_jsonl.LAW_ARTICLE_RANGE`에 적어 두고 문서목록 비고에도 자동 기록.

| 주제 | 법령 | 넣은 조문 |
|---|---|---|
| 임대차 신고 | 부동산거래신고법 시행령 | 제4조의3(신고 대상: 보증금 6천만 원 초과 또는 월 차임 30만 원 초과, 지역), 제20조(과태료) |
| 원상회복·중도 해지·보증금 | 민법 | 제618~654조 임대차 36개(삭제된 제651조 제외) |
| 전입신고 | 주민등록법 | 제10·11·16·16조의2·18조, 제29조의2(전입세대확인서), 제40조(과태료) |

- 넣지 않음: 공공주택 특별법 — 자격은 공고문에 구체적으로 있고, 법 본문은 사업자·분양 조항 위주.
- 결과: 법령가이드 426 → 471줄(조문 112 → 157), 전체 4,940 → 4,985줄, 문서목록 421 → 424행. 공공임대·청년안심 JSONL과 기존 조문의 id·본문은 변화 없음(git diff 확인).
- 조문 id는 법 전체 순서 번호를 유지(예: `LAW_CIVIL_본칙_627` = 민법 제618조).

## 5. 평가셋 [팀 공유]

### 5-1. 만든 방법

- 사용자 질문(사회초년생이 실제로 궁금한 것)에서 출발하고, 비는 이사 단계는 문서(조문·공고)에서 골라 채움.
- 질문마다 문서를 확인해 답 있음 / 답 없음 / 범위 밖으로 판정. 범위 밖은 제외.
- 정답(`key_facts`)과 근거는 원문을 보고 적음. 검색 결과로 적지 않음. 근거 발췌는 원문과 자동 대조(불일치 0).
- 답 없음 문항은 범위 안 주제인데 자료에 답이 없는 질문. 공유 JSONL 3개 전체에서 관련 단어가 없는지 확인.
- dev와 test는 같은 근거 줄을 쓰지 않게 설계.

## 6. A/B 검색 실험 — dev

- dev 10문항(답 있음 8 + 답 없음 2)으로만 봄. test는 실행 안 함.
- 지표 Hit@5: 답 있는 8문항 중 상위 5개에 허용 근거 줄이 하나라도 있는 수.

### 6-1. 설정 [개인]

| 항목 | 값 |
|---|---|
| 청크 | `jh_500`, `jh_1000` 비교 → 개선 1부터 `jh_1000` |
| A | `vectorstore.as_retriever(search_kwargs={"k": 5})`. 거의 같은 글 합치기를 할 때는 k=20에서 5개를 고름. 법령·가이드만 찾을 때는 `filter` |
| B | `BM25Retriever.from_documents(청크, preprocess_func=kiwi_tokenizer)`(k=20) + 벡터 검색기(k=20) → `EnsembleRetriever(retrievers=[bm25, vector], weights=[0.5, 0.5])`(안에서 RRF, c=60) → 상위 5 |
| BM25 단어 (`kiwi_tokenizer`) | r0~개선 2: 명사·숫자·외국어·한자·어근·동사·형용사(NNG·NNP·NR·SN·SL·SH·XR·VV·VA) / 개선 3: 동사·형용사(VV·VA) 빼고 흔한 일반 명사(때·경우·얼마·몇·사항·해당·등·것·수·후) 제외. 질문·청크에 같은 규칙 |
| 거의 같은 글 합치기 | 개선 1부터: 공백 뺀 글자 유사도 0.9 이상이면 먼저 나온 하나만(A·B 같은 후처리) |
| 문서 종류 나눠 찾기 | 개선 2부터: 질문에 공고·단지를 가리키는 말(공고·모집·행복주택·청년안심·LH·SH·단지 등, 주택형 `14A`, 역 이름 `○○역`)이 없으면 법령·가이드(`일반 전월세 법령`·`가이드`, jh_1000 중 545청크)에서만 찾음. 있거나 애매하면 전체. A는 `filter`, B는 법령·가이드 청크만으로 만든 `BM25Retriever` |
| 단계 선택 | `retrieve.PRESETS`(r0·dedupe·route·tok), `run.py --preset` |

### 6-4. 요약 [팀 공유]

- 조건: dev 10문항(답 있음 8 = 법령·가이드 6 + 공공임대 2), `RecursiveCharacterTextSplitter` 1000/200(법령 보강본 9,974청크), `text-embedding-3-small`, PGVector, A = 벡터 검색기, B = BM25Retriever + 벡터 검색기 → EnsembleRetriever.
- 최종: A 2/8, B 4/8. B가 A보다 나음 — BM25가 단지명·법 용어 같은 정확한 단어를 잡아 줌.
- 남은 4문항(월세 신고, 원상복구, 월세 인상, 계약금 취소)은 사용자 말과 문서 말이 달라 A/B로는 못 찾음 → 다음 단계(재정렬 C, 쿼리 리라이트)가 맡을 문제. 팀장 미니 실험(A 3/4, B 2/4, 구어체에서 B 악화)과 같은 원인.
- 평가셋 채점 주의: 같은 규칙이 법 조문과 가이드 여러 쪽에 있으므로 정답 근거를 한 곳만 적으면 맞게 찾아도 틀린 것으로 셈. 팀 평가셋도 허용 근거를 넓게 적는 것이 맞음.
- dev 답 있는 문항이 8개뿐이라 1~2문항 차이도 크게 보임.
