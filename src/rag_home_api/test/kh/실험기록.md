| 항목 | 값 |
|---|---|
| 입력 | `shared/docs/` JSONL 3개(공공임대·청년안심주택·일반전월세, 4,940줄) + 공급호실 CSV 2개(`public_housing_units`, `public_rent_scenarios`, 1,269호실) |

## 2. 청킹 전략 비교 (최종 v1 데이터 기준)

### 2-1. 무엇을 바꿨나

- **재귀 단독 (`RecursiveCharacterTextSplitter`)**: 문단(`\n\n`) → 줄바꿈(`\n`) → 문장(`. `) → 공백(` `) 순으로 `650/80` 또는 `600/100` 분할.
  - 한계: 긴 마크다운 표가 중간에서 잘려 **두 번째 조각부터 컬럼 헤더(`| 단지 | 보증금 | 월세 |`)가 사라지고**, 표 바로 위의 소제목(`2. 임대대상 및 임대조건`)만 단독 초단문 청크로 떨어져 나옴.
- **구조적 + 재귀 하이브리드 (`split_text_structured`)**:
  1. **1층(구조 분리)**: 페이지 본문을 `일반 글 블록`과 `마크다운 표 블록(|...| + |---|)`으로 분리.
  2. **2층(블록별 분할)**: 일반 글은 `600/100` 재귀 분할, 마크다운 표는 **행 단위로만 분할**하고 잘린 모든 표 조각 맨 위에 **원래 헤더 2줄을 자동 재부착**.
  3. **3층(구조 보정)**: 표 위 소제목 등 `120자` 미만 단독 조각이 남으면 바로 다음 청크 앞에 병합.
- **공급호실 CSV 통합 (`load_housing_unit_chunks`)**: `open() + csv.DictReader`로 두 CSV를 조인해 1호실 = 1청크(327~526자)로 조립하고, `district`·`min_deposit_krw`·`min_monthly_rent_krw`·`exclusive_area_m2`를 선택 메타데이터(`| None`)로 분리 저장.

### 2-3. 같은 쪽의 청크 비교 (LH 행복주택 공고 3쪽 임대조건표)

재귀 단독에서는 표 위 제목이 단독 청크(`c00`)로 떨어지고, 표 2번째 조각(`c02`)부터 헤더가 사라져 숫자의 의미를 알 수 없었다.

```text

[서울삼전,강동천호,LH수서1,LH수서2 행복주택 예비입주자 모집공고 | p.3]
2. 임대대상 및 임대조건
```

```text
[재귀 600/100 — 헤더 유실 & 행 절단] LH_2015122300021098_p003_c02
[서울삼전,강동천호,LH수서1,LH수서2 행복주택 예비입주자 모집공고 | p.3]

| 서울 삼전 | 26 | 신혼부부. 한부모가족 | 9 | 0 | 10 | 26.21 | 14.1806 | 12.6060 | 52.9966 |  <-- 행 중간 절단
```

## 4. 오류·실패 기록 (지우지 않음)

> 단순 오타로 난 오류는 적지 않는다.

| # | 단계 | 무슨 일이 있었나 | 원인 | 어떻게 했나 |
|---|---|---|---|---|
| ① | 3단계 로더 설계 | `pandas.read_json(..., lines=True)` 실험 시 가이드북 줄의 `article`이 `float('nan')`으로 바뀌고 `(val or "")`가 `nan` 그대로 남아 `.strip()` 에러 위험. `read_csv` 기본값에서는 호수 `0201` 앞자리 `0` 증발 우려 | 줄마다 키가 다른 JSONL·빈 옵션 칸이 많은 CSV를 DataFrame 표로 강제 통일할 때 발생하는 `NaN`·자동 형변환 | 텍스트 조립용 로더는 파이썬 표준 `open() + json.loads()` 및 `open() + csv.DictReader()`로 구현 (`pandas`는 추후 시세 집계용으로 분리) |
| ② | 3-2단계 호실 CSV | 1,269호실 청킹 실행 결과 `exclusive_area_m2`가 전부 `None`, 본문에 `전용면적: 미확인` 출력 | 면적 파싱 조건에 `u.get("exclusive_area_m2")` 대신 빈 컬럼 `u.get("housing_type_raw")`를 잘못 검사함 | 조건을 `u.get("exclusive_area_m2")`로 수정 → `25.15㎡` 복원 및 `content_hash` 자동 변경 확인 |
| ③ | 3단계 공고문 청킹 | 최종 v1 `공공임대_공고문.jsonl`을 `600/100` 재귀 분할했더니 마크다운 표 청크의 **45.6%(1,806개)**에서 헤더가 유실되고, 100자 미만 고아 제목 청크가 **518개** 발생 | `RecursiveCharacterTextSplitter`가 마크다운 표 구조와 소제목 연결을 모르고 글자 수·`\n\n`만으로 기계 분할함 | 3층 구조적 청킹(`_split_into_blocks` + `_split_table_preserving_header` + 120자 미만 제목 병합) 적용 → **표 헤더 유실 0%, 100자 미만 0.4%** |
| ④ | 6단계 검색 테스트 | PowerShell 파이프(`@'...'@ \| uv run python -`)로 한글 질문 3개를 실행했더니 `=== ?? ??: ????? ===`로 깨지며 엉뚱한 문서(`score=0.22~0.36`)만 검색됨 | Windows PowerShell 5.1의 파이프 기본 인코딩이 CP949라 UTF-8 한글이 물음표(`?`)로 변환된 채 OpenAI 임베딩 API에 전달됨 | 실행 전 `$OutputEncoding = [System.Text.UTF8Encoding]::new()` 및 `$env:PYTHONUTF8 = "1"` 지정으로 해결 |

## 6. 남은 한계 (아직 확인 못 함)

- **전체 데이터 미적재**: 현재 PGVector에는 소량 **216건**만 들어 있다. 최종 v1 전체(**16,397건**) 적재 후 검색 품질과 소요 시간·비용을 재측정해야 한다.
- **대형 표 청크 최대 길이(`최대 2,638자`)**: 행 중간 절단을 막다 보니 긴 단일 표 행이 2,600자대까지 커졌다. 임베딩 희석이나 생성기 컨텍스트 한도(`6,000자`)에 악영향이 없는지 검색 단계에서 확인 필요.
- **청년안심주택 1쪽 중복 안내문 도배**: 서로 다른 공고의 1쪽 안내문(`YOUTH_6806/6805/6804_p001`)이 Top-3 자리를 동시에 차지하는 현상 확인 → C(Re-ranking) 또는 중복 청크 억제 전략 검토 필요.
- **PGVector 전역 ID 유일성 주의**: 팀원 실험(오류 ①)에서 확인되었듯 `langchain_pg_embedding.id`는 컬렉션과 무관하게 테이블 전역에서 유일해야 한다. 추후 같은 DB에 여러 청킹/임베딩 버전을 동시에 올려 비교할 때는 `ids`에 버전 태그를 붙이거나 `rebuild=True`로 격리해야 한다.
- **전월세 실거래 CSV(562,624건) 및 반경 500m 공간 질의**: 현재 데이터에 위도·경도 좌표가 없고, 실거래 56만 건은 SQL 테이블 적재 미구현 (`eval/dev.json` `DEV-10`에 거절 평가 문항으로 반영).
- **최종 평가셋(`eval/test.json`) 20문항 미작성**: 개발용 `eval/dev.json` 10문항(답변 가능 8 + 근거 없음 2) 초안 작성 완료, 최종 `eval/test.json` 20문항은 전체 v1 적재 후 확정 예정.
